# CV delivery correction

The previous package was an application review, not a CV. The paid deliverable now requires a validated structured CV and keeps the review in a separate optional section.

The CV uses a single-column layout with professional summary, separate employer/title/date entries, grounded bullets, skills and education. No branding, analysis instructions or disclaimers are inserted into the applicant CV. Contact fields are added locally after fulfillment and are never sent to the server or AI provider. They are cleared when access expires or is revoked.

The provider must cite exact continuous source excerpts. Metadata and skills must occur in their evidence. Numeric claims require matching numeric tokens. Bullets cannot be moved across the detected source-employer blocks. These checks do not prove every semantic claim; the applicant must review the generated wording. A draft with missing experience metadata or skills cannot enter Checkout.

Before payment, the API returns fit evidence, gaps, completeness metadata and one original/rewritten bullet. It does not return the complete CV, employer chronology, original CV or full paid review. Full output uses ordinary ownership and verified-payment authorization. The owner diagnostic returns a fixed fictional CV only.

PDF downloads are generated directly as selectable text in the browser. Word uses OOXML styles and keeps role headings together with following content. Empty experience sections are omitted for education-led profiles. Long CVs can span pages. PDF currently uses standard Latin fonts; Word is the fallback for unsupported characters. The fictional public example is labelled as synthetic and is not a quality claim about all AI output.

Actual production/provider/sandbox verification must be recorded separately from mocked regression checks. Public AI and paid Checkout remain disabled pending the existing licence, data-processing, payment and tax launch reviews.
